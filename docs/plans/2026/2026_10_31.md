# Inventory System

Last Updated: 2026-10-31

## Problem

The user is currently able to build pretty much anything inside the room. For example, he is able to install blocks, canvases, props, lamps, and fans, as well as move them around, customize their properties (i.e. object metadata), or delete them. The user is also free to customize his own player character's body parts. Customization of the in-game components is an already well-established feature in our project.

This game, however, still lacks a sense of progression because there is no way for the user to either "gain scores" or "level up". It is impossible for him to accumulate assets which are quantitatively measurable, which means that there is nothing which creates long-term motivation.

## Solution

### Inventory and Items

We need to let each user have his own inventory. Inside the DB, it will be a simple map (dictionary) of string keys and numerical values. Each string key represents the type of an item, and its numerical value represents the item's quantity. So, if the user's inventory contains a "dollar" key which has the value of 100, it will imply that the user owns 100 dollars.

There may potentially be many types of items in the future, and we might feel the necessity to implement a UI for displaying the user's inventory in a grid (or list) form (This means that, inside the codebase, the inventory system will need to have its own separate directory outside of the "user" directory, "object" directory, "room" directory, etc; it is because the inventory system might grow quite large in the future). For now, however, let us simply assume that there is only one type of item called "dollar", whose quantity will be displayed as a simple number text at the top-left corner of the screen (with a money icon on the left side - i.e. a simple green paper money symbol that is easy to discern from a distance).

### Collectibles

Let's make the server occasinally spawn a $1 bill (folded in half but flapping whenever a wind blows), simulate its random impulsive movements in terms of waypoints which do not penetrate through voxel blocks (in a manner similar to NPC movements, but with much shorter paths) and broadcast these movements to the clients. These movements should hypothetically be caused by occasional random gusts of wind, which flap & flutter the bill by fluctuating its body as a whole as well as the angle between its folded halves. That is, random invisible gusts of wind should occasionally blow the bill around in a random direction (but not in a direction which is directed toward any existing player). The bill's movement must also be affected by FanGameObject's continuously blowing wind (I think such a sudden fan-based push can be communicated to the clients in the form of waypoints/paths as well - just with a different move-speed which will result in a different rate at which the client will interpolate the bill's position in real time).

The server should spawn $1 bills after every 20s-60s interval (randomly chosen between 20s and 60s, inclusive) and at a random spot within the room that is neither inside any voxel block nor too close to any player (i.e. user). The server is also responsible to keep at most 4 bills per room at a time. As long as the room holds 4 bills and no one destroys any of them, the server won't spawn any new bill.

When the user's player character gets sufficiently close to a $1 bill (i.e. close enough to almost touch it, but with some extra margin so as not to be too strict when it comes to touch-detection), the bill should disappear with a sparkling VFX and increment the user's "dollar" item quantity by 1 (The quantity-displaying UI must briefly bounce and glow in order to emphasize the fact that it incremented).

For the rendering of the $1 bill mesh, I guess you can leverage the InstancedMeshGraphics system for efficiency. The texture for the $1 bill, I believe, can be just a small allocated texture area inside the atlas of PropGameObject, but I am not sure whether this approach will yield better performance than just creating a separate texture for the $1 bill. Please compare the alternatives and choose the best solution.
